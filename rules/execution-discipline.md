# Execution Discipline

- **先出数再写文。** 论文中的结果数值必须先由可执行代码落盘并进入 ledger。
  **检验**：随机抽一个正文数字，能否沿宏、ledger 的 source.file/source.field 回到磁盘结果和生成脚本？
- **先保住端到端最小闭环。** 模型定型后先以小规模跑通计算、入账、作图、论文、编译和打包，再提高精度。
  **检验**：当前磁盘上是否有一份可编译、可复现、数字虽粗但不造假的最差提交版本？
- **验证要求先于答案冻结。** 每问九字段拆问卡在求解前齐全，`validation_requirements` 在首次入账前锁定，`data_evidence` 只写已核事实或待核标记。
  **检验**：`objective/input_data/decision_variables/constraints/expected_outputs/dependencies/risks/validation_requirements/data_evidence` 是否逐问齐全且时间早于首次 ledger？
- **数据体检必须逐列给数字并撞题面。** 每个附件记录规模、量纲、分布、缺失异常及题面条款与实测值对照。
  **检验**：任取一列，能否看到实际统计量和对应题面声明，而非“正常”“已检查”？
- **读题完整性要独立复盘。** 完成拆问后只看原题再重建小问、定义、边界、单位与输出，再与拆问卡对表。
  **检验**：第二次重建是否发现未处置差异；存在 `BLOCKED` 时是否停止定型？
- **口径决策必须撞现实。** 每项可解释口径都挂一个若定错会异常的可观测量，并在生产批前实测。
  **检验**：每条口径能否补全“若定错，___ 会出现 ___”，且结果文件中已有该观测量？
- **跨问共用一个判定内核。** 各问只在输入、扫描或优化层分叉；内核变化后所有依赖结果标 stale 并重跑。
  **检验**：从各问调用点追踪，是否导向同一函数与同一对象身份、边界、判据定义？
- **机时可行性只认实测且长批可恢复。** 用真实内核小跑计时后外推，生产批按块原子落盘、启动时扫描续跑并保留资源余量。
  **检验**：预算表是否贴实际命令与耗时；中断当前进程后，已完成块能否被识别并跳过？
- **计算与作图分离。** 计算脚本只写结果与统计量，绘图脚本只读结果或 ledger，禁止在图代码里重算或硬编码答案。
  **检验**：删掉原始求解环境只保留结果文件，全部图是否仍能重画且读数不变？
- **入账前做合理性与派生量复算。** 极限、单调、量纲、量级、跨问关系、退化输出和汇总字段都用独立路径核对。
  **检验**：随机抽一个计数或汇总字段，能否从其来源结构直接重算一致；异常是否先停而非解释过去？
- **关键答案必须双路互证并检查稳定性。** 独立路线差异不得取平均或择优，随机结论还要用独立主种子复核报告精度。
  **检验**：ledger 的 cross_check 与 stability 是否给出两路数值、差异、种子和不一致处置？
- **声明与实现从代码取证。** 论文关键谓词与跨问一致性须指到代码行和实际条件，不能用论文自己的描述自证。
  **检验**：随机抽三句结论，能否列出 `论文原句 -> 代码行 -> 实际谓词` 且逐项一致？
- **关键结论必须集中可见。** 每问结尾放答案、证书、适用条件的结论块，全文另有逐问结果汇总表。
  **检验**：不阅读全文时，能否从结论块与汇总表找全各问唯一答案及证书位置？
- **模型检验必须独立成章。** 检验章覆盖双路互证、可核事实对表、参数灵敏度、样本量与收敛、稳健性对照、适用边界与失效域。
  **检验**：六项能否各指到包含数字的工件或图表；“已检验”而无证据的项按缺失处理。
- **图先有论证目的并紧跟解读。** 开画前绑定结论、ledger 键与正文落点，正文图后说明看见什么及为何影响取舍。
  **检验**：运行 `python scripts/figqa.py 图/ --tex 论文/*.tex`；再问每张图“删掉后哪条结论失去支撑？”
- **同一被问量只能有一个答案。** 摘要、正文、图表与结论引用同一 authoritative 值，互证值只在检验处标明角色。
  **检验**：按 quantity 全文搜索，数值、单位、精度与取整口径是否完全一致？
- **复现闭环必须有可执行入口。** 交付目录内的入口脚本须可达每个 authoritative source，并用包内相对路径重建最小核对子集。
  **检验**：在解压后的交付目录直接运行入口，是否无需工作区文件即可再生并核对 ledger 键？
- **门禁不接受空通过、口头通过或静默降级。** 被检对象、命令、预期、失败条件和退出码缺一即未执行；妥协当场记录。
  **检验**：每份 Gate 记录是否含官方命令与退出码；运行 `python -m pytest scripts/tests/test_contracts.py -q` 是否全绿？
- **官方脚本是门禁执行体。** 项目逻辑应成为官方脚本输入；自写替代检查不能给 authoritative 数字或 Gate 发证。（自写替代品会让所有门禁记录变成交付者给自己发的，坑点见 `references/gotchas.md#self-issued-gates`）
  **检验**：Gate 记录中的命令是否来自 `scripts/`，替换时是否有差异、理由与独立自证记录？
- **引用必须真实可核。** 最终参考文献逐条用 Crossref 或 OpenAlex 核标题、作者、期刊与 DOI，查不到就标注或删除。
  **检验**：每条引用是否保留查询结果或永久标识，正文是否确实使用了它支持的方法或事实？

## Rationalizations to Reject
| 实测借口 | 处理 |
|---|---|
| “测试和门禁都绿，答案就可信” | 运行现实判别与退化探针；机械通过不能证明解的是题面问题。 |
| “红线已在论文披露，可以继续” | 停止；披露不是修复，只有允许降级的主张才降措辞。 |
| “自写检查与官方脚本等价” | 不放行；项目逻辑作为官方脚本输入，替代品不能自发证书。 |
