# math-modeling-solve

数学建模竞赛的端到端求解 skill：读题 → 数据体检 → 口径审定 → 选模 → 计算 → 证书 →
深度审查 → 图表 → 论文 → 编译合规 → 打包复现。

给 Claude Code / Codex 用。把仓库整个放进 skills 目录即可，`SKILL.md` 在根。

---

## 一、它跟别的数模 skill 有什么不同

### 散文越少越好，退出码一个都不能少

这不是审美偏好，是实测结论。一份交付物曾自写 `emit_ledger.py`、`figures_mc.py`、
`rules_gate.py` 绕过官方脚本，结果**所有门禁记录都是交付者给自己发的**——
skill 里那些写得完全正确的规范（共享内核、独立神谕、证书分离、三向审计）一条都没真正执行，
而门禁看起来全绿。

规范可以被"我读过了、我遵守了"糊弄，`degenerate.py` 的退出码 1 糊弄不过去。

所以本 skill 的留存判据是：

> **一条规则要留下，要么它是退出码，要么它是换个更强模型重跑仍会犯的错。**
> 只有某道题会犯的、只有弱模型会犯的，都不进来。

按这把尺子，v3.3 把散文砍掉大半，脚本从 10 个加到 **17 个**。

### 赛制参数不在 skill 里

页数、图数、时限随赛事变，硬编码就是过拟合。它们在 `开题.md`，每场比赛填一次，
门禁从那里取参数，**没填就报错，不给兜底默认值**。

### 两条贯穿全程的纪律

| 纪律 | 含义 | 执行体 |
|---|---|---|
| **SDD：先规格，后执行** | 动手前先把"怎么算通过"写死。拆问卡的 `validation_requirements` **必须早于 ledger 落盘** | `task_cards.py` 比对 mtime |
| **TDD：第一性原理的红绿灯** | 建模与实现走最小实现 + 红绿 + 复现。神谕测试的 expected **不得来自被测代码** | `test_inventory.py`、`degenerate.py` |

**为什么必须是"先"**：有了答案再挑验证方法，挑的一定是刚好能过的那个。
记录在案的最大事故正是这个机制——92 项测试全绿、所有门禁全绿，答案错了近 70 倍，
因为测试是照着已有实现补的。

## 二、架构

```
SKILL.md        路由入口（description ≤25 行，正文 ≤90 行）——只说"读什么、什么时候读"
routing.yaml    任务 → workflow，6 条含 other 兜底；每条声明自己的 required_reads
CLAUDE.md       薄壳：上下文压缩后唯一幸存的东西
CODEX.md        同上（各自是对应工具的入口）
开题.md          每场比赛填一次的赛事参数
rules/          「我能做 X 吗」——红线 11+2 条，每条「原则 + 检验句」
workflows/      「我现在该做什么」——主链 + 4 条支线 + 兜底
references/     「这个坑怎么避」+ 角色职责维度——按触发条件跳读，不预加载
scripts/        17 个执行体 + 契约测试
assets/paper/   论文形态契约（cumcmthesis 分节模板，每节带写作合同）
```

**分层判据**：「我能做 X 吗」→ `rules/`；「这个坑怎么避」→ `references/`；
「我现在该做什么」→ `workflows/`。会话历史、调试过程、实验记录**一律不进 skill**。

### 路由

每个新任务读 `routing.yaml`，按 `labels` / `trigger_examples` / 任务意图**只匹配一条**：

| 路由 | 什么时候命中 |
|---|---|
| `solve-full` | 完整解题到交付包 |
| `solve-only` | 只求解、暂不写论文（"先做问题一"） |
| `paper-only` | 结果已在账本里，只写/改论文 |
| `latex-fix` | 编译或版面修错 |
| `gate-triage` | 某道门禁没过，要定位 |
| `other` | 兜底——先判断该走哪条 |

规则不全局预加载，而是**按路由带**：修 LaTeX 不会被迫读完建模红线。

### 门禁

| 脚本 | 它拦住过什么 |
|---|---|
| `degenerate.py` | 一份 92 项测试全绿的交付物，单体自导通 24.7%、阈值敏感性 0，答案错近 70 倍。**统计证书拦不住错的物理，这条 30 秒的检查能** |
| `seed_gate.py` | 三个独立种子族各跑满样本，判出三个相邻但不同的档位——答案随种子漂移即未分辨，必须降档报告 |
| `batch_gate.py` | 长批必须是可恢复状态机。一次性 `pool.map` 赌 18 万任务的脚本从未跑完过 |
| `certify.py` | 三态证书（可行／已排除／**证据不足**）。区间跨过阈值只能说"证据不足"；`--solve-n` 给出要多少样本才够 |
| `ledger.py` + `audit_numbers.py` | 唯一权威答案、依赖哈希冻结、论文↔台账↔结果文件三向审计 |
| `task_cards.py` | 每问九字段拆问卡，且验证方式必须早于答案落盘 |
| `pilot_gate.py` | 定型前每问 2–3 个候选加一个 baseline 真跑，只从跑通的里面定案 |
| `sample_gate.py` | 逐场景样本量与夹逼；相邻档必须有排除证据 |
| `figqa.py` | 图数、正文引用、空图重复图。生成的图没进论文＝论证链断了 |
| `latex_gate.py` | 编译阻断项 10 类、页数上下限、摘要页由 `.aux` 程序化核实 |
| `refs_check.py` | 参考文献逐条过 Crossref，编造的引用是 rules 维实打实的失分 |
| `pkg_scan.py` | 已判"合规全 PASS"的交付包里写着真实口令，差一步推上公开仓库 |
| `method_query.py` | 66 张方法卡按题意检索，返回少量候选及其**前提／会怎么死／怎么验** |
| `skill_smoke.py` | skill 自己的自检：行数预算、占位符残留、路由断链、薄壳承重结构、引用锚点 |

`scripts/tests/test_contracts.py` 把每个脚本承诺的行为钉成断言，当前 **62 项全过**。
**契约测试不过时，"官方脚本不可替代"这句话就是虚假确定性。**

## 三、开一道题的完整流程

单模型单会话就能跑完。下面是多角色配置下的完整链路——**箭头就是交接点，
每个交接点都带一份可检查的产物**，不是口头传话。

```
Coordinator 读题 ──► PRD ──► Modeler 建模 review ──┬─► 有异议 ─► Critic 对抗审查 ─┐
                                                    │                              │
                                                    └─────────── 无异议 ───────────┤
                                                                                   ▼
Finisher 打包 ◄── Coordinator 终裁 ◄── Auditor 复核 ◄── Writer 写作 ◄── Illustrator 出图 ◄── Coder 实现
```

| # | 阶段 | 角色 | 做什么 | 交出什么 |
|---|---|---|---|---|
| 1 | **P-1 规格** | **Coordinator** | 读赛题与格式规范；写 PRD（目标／边界／完成标准）；逐条打磨到每条完成标准都能回答「怎么算过、谁来判、用什么命令判」 | PRD + 题面分析 |
| 2 | 执行前评审 | **Modeler** | 独立复核 Coordinator 的建模思路（题型／方法族／主路线与核验路线是否真独立）；**有异议不执行，退回，不就地改** | 异议清单 或 「无异议，可执行」 |
| 3 | 对抗性审查 | **Critic** | 按第一性原理查疏漏：**复现了吗？红绿了吗？** 没参与实现的人来挑毛病 | 补充项，同步下发 |
| 4 | 实现与计算 | **Coder** | P0–P4：拆问卡、Pilot、共享内核、独立神谕测试、长批、证书、ledger 冻结 | 结果文件 + 冻结的账本 + 各 Gate 退出码 |
| 5 | 出图 | **Illustrator** | 三套并行：① 主控自出一套 ② 执行方按背景与源文件路径出一套 ③ 执行方模仿指定样例目录出一套；再生成**对照 HTML** | 三套图 + 对照页 |
| 6 | 写作 | **Writer** | 摘要、正文、六小节检验章、结论块与汇总表；数字只引用宏 | 论文 tex |
| 7 | **P6.5 复核** | **Auditor** | 拿**题目 + 交付物**核三件事：建模最优解有没有体现在文章里、公式有没有写坏、有没有按流程的规范文字写 | 复核意见 |
| 8 | 终裁与打包 | **Coordinator → Finisher** | 主控确认无误后下发；编译、合规、复现闭环、出门扫描、打包 | 交付包 |

### 规格关是硬门禁

**PRD 未过打磨关之前，禁止定方法路线、禁止写实现文档、禁止动代码、禁止跑计算。**

这条借自 Trellis-Herbivore 的 planning 门禁（`trellis-brainstorm` → `trellis-grill-me`
完成之前不许做策略决策、不许写 design/implement、不许 start），与本 skill 的 SDD 纪律是同一件事：
规格没写死就开工，等于让「怎么算通过」由结果反向决定。

### 出图的三选一

第 5 步默认**直接采用主控那一套**——用这个 skill 生成文章必然要引用图，流程不能停下来等人选。
对照 HTML 是留给你事后看的接口：看完告诉主控选哪套，替换即可，其余环节不受影响。

样例目录在 `开题.md` 的「目标图样例目录」里指定；模仿的是版面与色彩编码，
**长相可以仿，数字一个都不许仿**——图里每个数必须来自 `results_ledger.json`。

### 交接点的硬要求

- 第 2 步**不是走过场**：Modeler 没做 review 就开工，等于把第 3 步的对抗性审查一起跳过了。
- 第 3 步的价值全在「**没参与**」：作者复核自己的实现，看到的是"我以为我写了什么"。
- 第 7 步至少要给 Auditor **题目原文与交付物**——只给论文，它核不了"最优解有没有体现进去"。

## 四、角色与模型

每个角色的**职责维度与交接验收单**见 [`references/roles.md`](references/roles.md)——一句话职责在交接时没法验收。模型推荐默认如下，**想换随时可以，开工前说一句就行**——skill 约束的是产物与退出码，不是谁来产出。

| 角色 | 推荐模型 | 为什么是它 |
|---|---|---|
| **Coordinator** | Claude Opus | **建模思路的原创者**——题型、方法族、主路线与核验路线由它定；读题细致度与判断力错在这里后面全白做 |
| **Modeler** | Codex（`sol`，max goal） | **复核者不是原创者**——独立复核 Coordinator 那份思路站不站得住，要能提出实质异议而不是复述 |
| **Critic** | Claude Opus | 对抗性审查，按第一性原理挑毛病 |
| **Coder** | Codex（`sol`，max goal） | 大量写代码、跑批、修编译错误，要的是稳和快 |
| **Illustrator** | Opus + Codex（`sol`，max goal） | 两方各出一套再加一套模仿版，横向比较 |
| **Writer** | Claude Opus | 写作质量 |
| **Auditor** | Codex（`astra`，medium） | 复核不需要最强推理，需要的是没参与过 |
| **Finisher** | Codex（`terra`，max） | 编译、合规、打包，机械但要一次做对 |

### 两个模型的共同底线

无论谁执行，两条不变：

1. **先按 SDD 规格，再执行**——动手前"怎么算通过"必须已经写死；
2. **建模遵循第一性原理**——TDD 的最小实现红绿灯，加上可复现。

第 3 步 Critic 的两个问题（**复现了吗？红绿了吗？**）就是这两条的验收句。

### 前置依赖（可降级，不装也能跑）

P-1 那套「一次问一个、问到收敛，再逐条打磨」的做法不是单一 skill，是三处拼起来的：

| 来源 | 提供什么 |
|---|---|
| [mindfold-ai/Trellis](https://github.com/mindfold-ai/Trellis) | task 目录、`prd.md`、上下文注入、implement/check 代理 |
| [LonelyHerbivore/Trellis-Herbivore](https://github.com/LonelyHerbivore/Trellis-Herbivore) | 魔改工作流：brainstorm → grill-me → PRD → implement，并把 grill-me 定为**必过门禁** |
| [mattpocock/skills](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md) | grill-me 的原始思路；Herbivore 已内置替代实现，**装了 Herbivore 就不必再装它** |

**本仓不携带这三者**，也不依赖它们。装了就用它们跑 P-1；没装就降级为
Coordinator 直接手写 PRD——目标、边界、完成标准（Done When）三节，再逐条打磨一遍，
**门禁语义完全一样**：每条完成标准都要能回答「怎么算过、谁来判、用什么命令判」。

## 五、使用

### 装

把整个仓库放进 skills 目录：

```
~/.claude/skills/math-modeling-solve/     # Claude Code
```

Codex 侧读根目录的 `CODEX.md`。两份薄壳把路由表内联进去，**上下文压缩后它们是最后一道防线**。

### 填 `开题.md`

每场比赛填一次，照赛事的论文格式规范原文抄，不要凭印象：

```yaml
赛事: 高教社杯全国大学生数学建模竞赛
正文页数上限: 20          # → latex_gate.py --max-body-pages
总页数下限: 40            # → latex_gate.py --min-pages
图总数下限: 12            # → figqa.py --min-figures
正文引用图下限: 8         # → figqa.py --min-body-figures
摘要页数: 1
论文模板: 官方 class 优先；无官方模板时用 assets/paper/format.cls
目标图样例目录: <你自己的期刊图样例目录>
总时限: 72h
主计算机时上限: 20h
本机核数: 32
```

**页数下限按高分档定，不按"能交差"定**——实测有一轮交付物精确停在当时写的下限上，
逐条合规却在图表维直接 0 分。地板就是模型会停的地方。

### 开工

把赛题 PDF、附件、格式规范放进工作目录，说一句人话即可：

- 「帮我完整解这道数模题并写成论文」→ `solve-full`
- 「先做问题一，论文回头再说」→ `solve-only`
- 「结果已经算好了，只帮我写论文」→ `paper-only`

不需要背命令。路由自己匹配，workflow 在每一步给出要跑的门禁命令。
