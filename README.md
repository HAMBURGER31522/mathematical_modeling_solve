# math-modeling-solve

数学建模竞赛的端到端求解 skill：读题 → 数据体检 → 口径审定 → 选模 → 计算 → 证书 →
深度审查 → 图表 → 论文 → 编译合规 → 打包复现。

给 Claude Code / Codex 用。把仓库整个放进 skills 目录即可，`SKILL.md` 在根。

---

## 一、它跟别的数模 skill 有什么不同

### 散文越少越好，退出码一个都不能少

这不是审美偏好，是实测结论。一份交付物曾自写 `emit_ledger.py`、`figures_mc.py`、
`rules_gate.py` 绕过官方脚本，结果**所有门禁记录都是交付者给自己发的**——
skill 里那些写得完全正确的规范（共享内核、独立神谕、证书分离、三向审计）一条都没真正执行，
而门禁看起来全绿。

规范可以被"我读过了、我遵守了"糊弄，`degenerate.py` 的退出码 1 糊弄不过去。

所以本 skill 的留存判据是：

> **一条规则要留下，要么它是退出码，要么它是换个更强模型重跑仍会犯的错。**
> 只有某道题会犯的、只有弱模型会犯的，都不进来。

按这把尺子，v3.3 把散文从 1423 行砍掉大半，脚本从 10 个加到 **17 个**。

### 赛制参数不在 skill 里

页数、图数、时限随赛事变，硬编码就是过拟合。它们在 `开题.md`，每场比赛填一次，
门禁从那里取参数，**没填就报错，不给兜底默认值**。

### 三条纪律是"先声明后验证"

| 纪律 | 执行体 | 为什么 |
|---|---|---|
| 拆问卡的 `validation_requirements` **必须早于 ledger 落盘** | `task_cards.py` 比对 mtime | 有了答案再挑验证方法，挑的一定是刚好能过的那个 |
| 神谕测试的 expected **不得来自被测代码** | `test_inventory.py` + 抽查检验句 | 否则测试只是在复述实现 |
| Pilot 候选**必须同数据划分、且属于本轮协议** | `pilot_gate.py` | 防止旧一轮的结果冒充新实验 |

## 二、架构

```
SKILL.md        路由入口（description ≤25 行，正文 ≤90 行）——只说"读什么、什么时候读"
routing.yaml    任务 → workflow，6 条含 other 兜底；每条声明自己的 required_reads
CLAUDE.md       薄壳：上下文压缩后唯一幸存的东西
CODEX.md        同上（两份内容一致，各自是对应工具的入口）
开题.md          每场比赛填一次的赛事参数
rules/          「我能做 X 吗」——红线 11+2 条，每条「原则 + 检验句」
workflows/      「我现在该做什么」——主链 + 4 条支线 + 兜底
references/     「这个坑怎么避」——按触发条件跳读，不预加载
scripts/        17 个执行体 + 契约测试
assets/paper/   论文形态契约（cumcmthesis 分节模板，每节带写作合同）
```

**分层判据**（决定一段内容该放哪）：
"我能做 X 吗" → `rules/`；"这个坑怎么避" → `references/`；"我现在该做什么" → `workflows/`。
会话历史、调试过程、实验记录**一律不进 skill**——那是 git 的事。

### 路由

每个新任务读 `routing.yaml`，按 `labels` / `trigger_examples` / 任务意图**只匹配一条**：

| 路由 | 什么时候命中 |
|---|---|
| `solve-full` | 完整解题到交付包 |
| `solve-only` | 只求解、暂不写论文（"先做问题一"） |
| `paper-only` | 结果已在账本里，只写/改论文 |
| `latex-fix` | 编译或版面修错 |
| `gate-triage` | 某道门禁没过，要定位 |
| `other` | 兜底——先判断该走哪条 |

规则不是全局预加载，而是**按路由带**：修 LaTeX 不会被迫读完建模红线。

### 门禁

| 脚本 | 它拦住过什么 |
|---|---|
| `degenerate.py` | 一份 92 项测试全绿、G0–G7 全绿的交付物，单体自导通 24.7%、阈值敏感性 0，答案错近 70 倍。**统计证书拦不住错的物理，这条 30 秒的检查能** |
| `seed_gate.py` | 三个独立种子族各跑满样本，判出三个相邻但不同的档位——答案随种子漂移即未分辨，必须降档报告 |
| `batch_gate.py` | 长批必须是可恢复状态机。一次性 `pool.map` 赌 18 万任务的脚本从未跑完过 |
| `certify.py` | 三态证书（可行／已排除／**证据不足**）。区间跨过阈值只能说"证据不足"，不能说"不可行"；`--solve-n` 给出要多少样本才够 |
| `ledger.py` + `audit_numbers.py` | 唯一权威答案、依赖哈希冻结、论文↔台账↔结果文件三向审计 |
| `task_cards.py` | 每问九字段拆问卡，且验证方式必须早于答案落盘 |
| `pilot_gate.py` | 定型前每问 2–3 个候选加一个 baseline 真跑，只从跑通的里面定案 |
| `sample_gate.py` | 逐场景样本量与夹逼；相邻档必须有排除证据 |
| `figqa.py` | 图数、正文引用、空图重复图。生成的图没进论文＝论证链断了 |
| `latex_gate.py` | 编译阻断项 10 类、页数上下限、摘要页由 `.aux` 程序化核实 |
| `refs_check.py` | 参考文献逐条过 Crossref，编造的引用是 rules 维实打实的失分 |
| `pkg_scan.py` | 已判"合规全 PASS"的交付包里写着真实口令，差一步推上公开仓库 |
| `method_query.py` | 66 张方法卡按题意检索，返回少量候选及其**前提／会怎么死／怎么验** |
| `skill_smoke.py` | skill 自己的自检：行数预算、占位符残留、路由断链、薄壳承重结构、引用锚点 |

`scripts/tests/test_contracts.py` 把每个脚本在文档里承诺的行为钉成断言，当前 **52 项全过**。
**契约测试不过时，"官方脚本不可替代"这句话就是虚假确定性。**

## 三、使用

### 1. 装

把整个仓库放进 skills 目录：

```
~/.claude/skills/math-modeling-solve/     # Claude Code
```

Codex 侧读根目录的 `CODEX.md`。两份薄壳把路由表内联进去，**上下文压缩后它们是最后一道防线**。

### 2. 填 `开题.md`

每场比赛填一次，照赛事的论文格式规范原文抄，不要凭印象：

```yaml
赛事: 高教社杯全国大学生数学建模竞赛
正文页数上限: 20          # → latex_gate.py --max-body-pages
总页数下限: 40            # → latex_gate.py --min-pages
图总数下限: 12            # → figqa.py --min-figures
正文引用图下限: 8         # → figqa.py --min-body-figures
摘要页数: 1
论文模板: 官方 class 优先；无官方模板时用 assets/paper/format.cls
目标图样例目录: <你自己的期刊图样例目录>
总时限: 72h
主计算机时上限: 20h
本机核数: 32
```

**页数下限按高分档定，不按"能交差"定**——实测有一轮交付物精确停在当时写的下限上，
逐条合规却在图表维直接 0 分。地板就是模型会停的地方。

### 3. 开工

把赛题 PDF、附件、格式规范放进工作目录，然后说一句人话即可，例如：

- 「帮我完整解这道数模题并写成论文」→ `solve-full`
- 「先做问题一，论文回头再说」→ `solve-only`
- 「结果已经算好了，只帮我写论文」→ `paper-only`

不需要背命令。路由会自己匹配，workflow 会在每一步给出要跑的门禁命令。

## 四、角色分配（推荐，可改）

这个 skill **单模型单会话就能跑完**，不依赖多智能体。下面是实测下来分工更划算的配置——
各阶段对能力的需求确实不同，但**这是使用建议，不是运行时机制**。

想换模型随时可以，**开工前说一句就行**（例如"这次 P3 也用 Claude 跑"），
skill 不会因为换了模型而失效——它约束的是产物与退出码，不是谁来产出。

| 角色 | 负责 | 推荐默认 | 为什么是它 |
|---|---|---|---|
| **主控** | P0–P2 读题、口径审定、拆问卡、选模、Pilot 定型；全程裁决与验收 | **Claude Opus** | 这几步吃的是读题细致度与判断力，错在这里后面全白做；也是唯一需要跟你来回确认的阶段 |
| **执行** | P3 实现与计算、长批执行、门禁跑通、P7 编译打包 | **Codex（执行档）** | 大量写代码、跑批、修编译错误，要的是稳和快，不是每步都重新权衡 |
| **写作** | P5–P6 图表与论文、摘要、检验章 | **Codex（写作档）／Claude** | 形态契约已经写死在 `assets/paper/` 各节顶部，照着填即可；配 `abstract-moves.md` 与 `figure-style.md` |
| **复核** | P4 深度审查：声明↔实现抽查、跨问一致性、量级外部对照 | **另开一个干净会话** | 关键不在换厂商，在**没参与实现**。作者复核自己的实现，看到的是"我以为我写了什么" |

**复核那条最容易被省掉，也最不该省。** 我方记录在案的最大事故是：92 项测试全绿、
所有门禁全绿的交付物，答案错了近 70 倍——因为测试是照着已有实现补的。
拿一个没读过你代码的会话去核，成本极低。

### 不采用的分工

Remit 那类工作台把 Coordinator / Modeler / Coder / Writer 拆成四个常驻角色、各接不同厂商模型。
本 skill **不这么做**：那套分工的前提是给每个角色配不同供应商，角色多了交接损耗也上来了。
这里只分四档、且只是建议，路由与门禁都不依赖它。

同理**不做跨模型盲评**：某个模型在某处会出错，那是模型的问题，不该让 skill 为此变重。
