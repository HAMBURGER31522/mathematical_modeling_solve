# math-modeling-solve

数学建模竞赛的端到端求解 skill：读题 → 规格 → 建模详要 → 数据体检 → 口径审定 →
选模与试跑 → 计算与证书 → 深度审查 → 图表 → 论文 → 复核 → 编译合规 → 打包复现。

给 Claude Code / Codex 用。把仓库整个放进 skills 目录即可，`SKILL.md` 在根。

---

## 一、它跟别的数模 skill 有什么不同

### 散文越少越好，退出码一个都不能少

这不是审美偏好，是实测结论。一份交付物曾自写 `emit_ledger.py`、`figures_mc.py`、
`rules_gate.py` 绕过官方脚本，结果**所有门禁记录都是交付者给自己发的**——
skill 里那些写得完全正确的规范（共享内核、独立神谕、证书分离、三向审计）一条都没真正执行，
而门禁看起来全绿。

规范可以被"我读过了、我遵守了"糊弄，`degenerate.py` 的退出码 1 糊弄不过去。

所以本 skill 的留存判据是：

> **一条规则要留下，要么它是退出码，要么它是换个更强模型重跑仍会犯的错。**
> 只有某道题会犯的、只有弱模型会犯的，都不进来。

按这把尺子，v3.3 把散文砍掉大半，脚本从 10 个加到 **19 个**。

### 赛制参数不在 skill 里

页数、图数、时限随赛事变，硬编码就是过拟合。它们在 `开题.md`，每场比赛填一次，
门禁从那里取参数，**没填就报错，不给兜底默认值**。

### 两条贯穿全程的纪律

| 纪律 | 含义 | 执行体 |
|---|---|---|
| **SDD：先规格，后执行** | 动手前先把"怎么算通过"写死。建模详要与拆问卡的 `validation_requirements` **必须早于结果落盘** | `design_gate.py`、`task_cards.py` 比对 mtime |
| **TDD：第一性原理的红绿灯** | 建模与实现走最小实现 + 红绿 + 复现。神谕测试的 expected **不得来自被测代码** | `test_inventory.py`、`degenerate.py` |

**为什么必须是"先"**：有了答案再挑验证方法，挑的一定是刚好能过的那个。
记录在案的最大事故正是这个机制——92 项测试全绿、所有门禁全绿，答案错了近 70 倍，
因为测试是照着已有实现补的。

### 它防的是哪些事故

`references/gotchas.md` 里 10 条，全部来自真实翻车，每条按「具体发现 → 通用 pattern → 后果」写：

| 坑 | 一句话 |
|---|---|
| 门禁全绿却解错问题 | 统计证书只能证明所实现的问题，不能证明题意和物理口径正确 |
| 语义身份 | 行号、块序、显示名不是稳定主键——数字、图与正文会彼此一致地指错对象 |
| 长批全损 | 长计算是可恢复状态机，不是一次函数调用 |
| 估时代替实测 | 复杂度符号不能替代真实内核计时 |
| 图生成了没被引用 | 生成文件不等于建立证据链 |
| 自发门禁 | 被检实现不能自行定义通过标准 |
| 交付边界泄漏 | 工作区与交付包是两个安全边界 |
| 证据不足 ≠ 不可行 | 二态化会系统性劣化答案并伪装成稳健 |
| 答案随种子漂移 | 阈值附近的档位选择是随机变量，单族结论只是一次实现 |
| 随机几何/渗流专有 | 命中该题型后再读，不是通用红线 |

## 二、架构

```
SKILL.md        路由入口（description ≤25 行，正文 ≤90 行）——只说"读什么、什么时候读"
routing.yaml    任务 → workflow，6 条含 other 兜底；每条声明自己的 required_reads
CLAUDE.md       薄壳：上下文压缩后唯一幸存的东西
CODEX.md        同上（各自是对应工具的入口）
开题.md          每场比赛填一次的赛事参数 + 角色到模型的映射
rules/          「我能做 X 吗」——2 份：建模红线 11+2 条、执行纪律；每条「原则 + 检验句」
workflows/      「我现在该做什么」——6 份：主链 + 4 条支线 + 兜底
references/     「这个坑怎么避」+ 角色维度 + 摘要 move + 图式卡 + 方法卡——按触发条件跳读
scripts/        19 个执行体 + 契约测试
assets/paper/   论文形态契约（cumcmthesis 分节模板，每节带写作合同）
```

**分层判据**：「我能做 X 吗」→ `rules/`；「这个坑怎么避」→ `references/`；
「我现在该做什么」→ `workflows/`。会话历史、调试过程、实验记录**一律不进 skill**。

### 路由

每个新任务读 `routing.yaml`，按 `labels` / `trigger_examples` / 任务意图**只匹配一条**：

| 路由 | 什么时候命中 | 带哪些规则 |
|---|---|---|
| `solve-full` | 完整解题到交付包 | 建模红线 + 执行纪律 |
| `solve-only` | 只求解、暂不写论文（"先做问题一"） | 建模红线 + 执行纪律 |
| `paper-only` | 结果已在账本里，只写/改论文 | 执行纪律 |
| `latex-fix` | 编译或版面修错 | 无固定必读 |
| `gate-triage` | 某道门禁没过，要定位 | 执行纪律 |
| `other` | 兜底——先判断该走哪条 | 先读 routing.yaml |

规则不全局预加载，而是**按路由带**：修 LaTeX 不会被迫读完建模红线。

### 门禁：什么时候跑什么

| 阶段 | 门禁 | 它拦住过什么 |
|---|---|---|
| P-1 规格 | `design_gate.py` | 建模详要逐问十项齐全且**每项有实质内容**——只有标题没内容按缺项处理 |
| P-1 规格 | `openconf.py` | 赛事参数缺一即报错，不给兜底默认值 |
| P0 读题 | `task_cards.py` | 每问九字段拆问卡，且**验证方式必须早于答案落盘** |
| P2 选模 | `method_query.py` | 66 张方法卡按题意检索，返回候选及其**前提／会怎么死／怎么验** |
| P2 选模 | `pilot_gate.py` | 每问 2–3 个候选加一个 baseline 真跑，同数据划分，只从跑通的定案 |
| P3 实现 | `test_inventory.py` | 测试实收数 vs 声称数，防「我写了测试」的口头账 |
| P3 实现 | `degenerate.py` | 一份 92 项测试全绿的交付物，单体自导通 24.7%、阈值敏感性 0，答案错近 70 倍。**统计证书拦不住错的物理，这条 30 秒的检查能** |
| P3 长批 | `batch_gate.py` | 长批必须是可恢复状态机。一次性 `pool.map` 赌 18 万任务的脚本从未跑完过 |
| P3 认证 | `certify.py` | 三态证书（可行／已排除／**证据不足**）；`--solve-n` 给出要多少样本才够 |
| P3 认证 | `sample_gate.py` | 逐场景样本量与夹逼；相邻档必须有排除证据 |
| P3 认证 | `seed_gate.py` | 三个独立种子族各跑满样本，判出三个相邻但不同的档位——答案随种子漂移即未分辨 |
| P3 入账 | `ledger.py` | 唯一权威答案、语义主键、依赖哈希冻结、stale 传播、宏发射 |
| P5 图表 | `figqa.py` | 图数、正文引用、空图重复图。生成的图没进论文＝论证链断了 |
| P6 论文 | `audit_numbers.py` | 论文 ↔ 台账 ↔ 结果文件三向审计，含未走宏的数字清单 |
| P6 论文 | `refs_check.py` | 参考文献逐条过 Crossref，编造的引用是 rules 维实打实的失分 |
| P7 打包 | `latex_gate.py` | 编译阻断项 10 类、页数上下限、摘要页由 `.aux` 程序化核实 |
| P7 打包 | `pkg_scan.py` | 已判「合规全 PASS」的交付包里写着真实口令，差一步推上公开仓库 |
| 维护 | `skill_smoke.py` | skill 自己的自检：行数预算、占位符残留、路由断链、薄壳承重结构、引用锚点 |

`scripts/tests/test_contracts.py` 把每个脚本承诺的行为钉成断言，当前 **98 项全过**。
**契约测试不过时，"官方脚本不可替代"这句话就是虚假确定性。**

每一步都留下可检查的东西，交接靠产物不靠口头：

| 阶段 | 产物 |

| P0 | `结果/拆问卡.md`、`结果/数据体检.md`、`结果/results_ledger.json` |
| P2 | `求解/qN/选型.md`、`结果/pilot_results.json` |

## 三、开一道题的完整流程

单模型单会话就能跑完。下面是多角色配置下的完整链路——**箭头就是交接点，
每个交接点都带一份可检查的产物**，不是口头传话。

```
Coordinator 读题并写 PRD + 建模详要 ─► Modeler 独立复核
             ▲                              │
             └──── 有异议：退回修订后再复核 ──┘
                                            │ 无异议
                                            ▼
Coder 实现与计算 ─► Critic P4 科学证伪 ─► Illustrator 出图 ─► Writer 写作 ─► Auditor P6.5 复核 ─► Coordinator 终裁 ─► Finisher 打包
```

| # | 阶段 | 角色 | 做什么 | 交出什么 |
|---|---|---|---|---|
| 1 | **P-1 规格** | **Coordinator** | 读赛题与格式规范；写 PRD 并逐条打磨；再写**建模详要**——逐问十项（题型／三要素／主路线／独立核验路线／承重假设／口径／证书预告／分辨率／数据接口／已知失败模式），`design_gate.py` 退出码 0 | PRD + **建模详要** + 题面分析 |
| 2 | 执行前评审 | **Modeler** | 独立复核那份建模思路（题型／方法族／主路线与核验路线是否真独立）；**有异议不执行，退回 Coordinator 修订，修订后再复核** | 异议清单 或「无异议，可执行」 |
| 3 | **P0–P3 实现与计算** | **Coder** | 按放行后的最终规格完成拆问卡、Pilot、共享内核、独立神谕测试、长批、证书与 ledger 冻结 | 实际代码与结果 + 冻结的账本 + 测试、证书、复现材料及各 Gate 退出码 |
| 4 | **P4 计算后科学证伪** | **Critic** | 只对实际代码、运行结果、测试、证书、复现材料、规模与声明做证伪；不参与 P2 | 带证据位置的缺陷清单，退回 Coder；规格错误退回 Coordinator |
| 5 | 出图 | **Illustrator** | 三套并行：① 主控自出 ② 执行方按背景与源文件路径出 ③ 执行方模仿指定样例目录出；再生成**对照 HTML** | 三套图 + 对照页 |
| 6 | 写作 | **Writer** | 摘要、正文、六小节检验章、结论块与汇总表；数字只引用宏 | 论文 tex |
| 7 | **P6.5 复核** | **Auditor** | 拿**题面原文 + 全部交付物**核十条：最优解是否入文、公式有无写坏、规范文字、数字一致性、证书措辞、图文对应、越级主张、赛制合规、复现声明属实、未决项交代 | 逐条给证据位置的复核意见 |
| 8 | 终裁与打包 | **Coordinator → Finisher** | 主控确认无误后下发；编译、合规、复现闭环、出门扫描、打包 | 交付包 |

### 规格关是硬门禁

**PRD 与建模详要未过关之前，禁止定方法路线、禁止写实现文档、禁止动代码、禁止跑计算。**

这条借自 Trellis-Herbivore 的 planning 门禁（`trellis-brainstorm` → `trellis-grill-me`
完成之前不许做策略决策、不许写 design/implement、不许 start），与本 skill 的 SDD 纪律是同一件事：
规格没写死就开工，等于让「怎么算通过」由结果反向决定。

### 建模详要为什么是最要紧的一份

**下游拿它去执行。写薄了，执行方只能自己重新推导——于是两方各建各的模型，
Modeler 的执行前规格复核就退化成两套方案互相比较，而不是复核。**

审查的对象应当是**已给出的思路**，不是执行方自己另造一个。所以它不能是一行说明，
必须逐问成章；`design_gate.py` 会检查**每项标题下有没有实质内容**——
标题都在、每节一句话，肉眼极难判，而它恰恰是最上游、错了代价最大的那份产物。

### 出图的三选一

第 5 步默认**直接采用主控那一套**——用这个 skill 生成文章必然要引用图，流程不能停下来等人选。
对照 HTML 是留给你事后看的接口：看完告诉主控选哪套，替换即可，其余环节不受影响。

样例目录在 `开题.md` 的「目标图样例目录」里指定；模仿的是版面与色彩编码，
**长相可以仿，数字一个都不许仿**——图里每个数必须来自 `results_ledger.json`。

### 交接点的硬要求

- 第 2 步**不是走过场**：有异议必须退回 Coordinator 修订并重新复核，放行前 Coder 不得开工。
- 第 4 步只审已有的真实产物；Critic 不参与 P2，缺陷退回 Coder 修正并重跑受影响门禁。
- 第 7 步至少要给 Auditor **题面原文与交付物**——只给论文，它核不了"最优解有没有体现进去"。

## 四、角色与模型

每个角色的**职责维度与交接验收单**见 [`references/roles.md`](references/roles.md)——
一句话职责在交接时没法验收：「Coder 负责实现」，交回来的东西是好是坏没有对照物。
八个角色共 **65 条维度**，逐条对照，缺项即退回。

模型推荐默认如下，**想换随时可以，开工前说一句就行**——skill 约束的是产物与退出码，不是谁来产出。

| 角色 | 维度 | 推荐模型 | 为什么是它 |
|---|---|---|---|
| **Coordinator** | 8 | Claude Opus | **建模思路的原创者**——题型、方法族、主路线与核验路线由它定；读题细致度与判断力错在这里后面全白做 |
| **Modeler** | 7 | Codex（`astra`，medium） | **复核者不是原创者**——用独立上下文审查 Opus 给出的思路；异议退回 Opus，由 Opus 定稿后再交执行 |
| **Coder** | 8 | Codex（`gpt-5.6-sol`，max） | 按最终规格完成建模实现、计算、跑批与门禁，要的是稳和快 |
| **Critic** | 10 | Claude Opus | P4 只对真实代码、结果、测试、证书、复现、规模与声明做计算后科学证伪 |
| **Illustrator** | 7 | Opus + Codex（`sol`，max goal） | 两方各出一套再加一套模仿版，横向比较 |
| **Writer** | 8 | Claude Opus | 写作质量 |
| **Auditor** | 10 | Codex（`astra`，medium） | P6.5 对成稿与全部交付物做跨产物一致性和合规复核 |
| **Finisher** | 7 | Codex（`terra`，max） | 编译、合规、打包，机械但要一次做对 |

Modeler、Critic、Auditor 默认使用未参与其审查对象创作的新会话。若同一会话参与过被审阶段，
审查记录必须标记 `independence: degraded`，不得宣称完成了独立审查；模型厂商不同不自动等于独立。

Modeler 与 Auditor 虽都可使用 Astra medium，但不是同一次复核：前者在计算前审查建模规格，
后者在论文完成后审查全部交付物；两者分别使用独立上下文。

### 两个模型的共同底线

无论谁执行，两条不变：

1. **先按 SDD 规格，再执行**——动手前"怎么算通过"必须已经写死；
2. **建模遵循第一性原理**——TDD 的最小实现红绿灯，加上可复现。

第 4 步 Critic 的入口两问（**复现了吗？红绿了吗？**）就是这两条的验收句；
往下的压力测试（Pre-Mortem／Inversion／Second-Order）与反浅层要求见 roles.md 的 R9、R10。

### 前置依赖（可降级，不装也能跑）

P-1 分为 P-1a 规格与 P-1b 建模详要，完整规则见 [`workflows/solve-full.md`](workflows/solve-full.md)；可选 Trellis grilling 不可用时按同一门禁语义降级。

| 来源 | 提供什么 |
|---|---|
| [mindfold-ai/Trellis](https://github.com/mindfold-ai/Trellis) | task 目录、`prd.md`、上下文注入、implement/check 代理、`first-principles-thinking` |
| [LonelyHerbivore/Trellis-Herbivore](https://github.com/LonelyHerbivore/Trellis-Herbivore) | 魔改工作流：brainstorm → grill-me → PRD → implement，并把 grill-me 定为**必过门禁** |
| [mattpocock/skills](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md) | grill-me 的原始思路；Herbivore 已内置替代实现，**装了 Herbivore 就不必再装它** |

**本仓不携带这三者**，也不依赖它们。装了就用它们跑 P-1；没装就降级为
Coordinator 直接手写 PRD 与建模详要，**门禁语义完全一样**：每条完成标准都要能回答
「怎么算过、谁来判、用什么命令判」，建模详要仍要过 `design_gate.py`。

## 五、使用

### 装

把整个仓库放进 skills 目录：

```
~/.claude/skills/math-modeling-solve/     # Claude Code
```

Codex 侧读根目录的 `CODEX.md`。两份薄壳把路由表内联进去，**上下文压缩后它们是最后一道防线**。

### 填 `开题.md`

每场比赛填一次，照赛事的论文格式规范原文抄，不要凭印象：


### 开工

把赛题 PDF、附件、格式规范放进工作目录，说一句人话即可：

| 你说 | 命中 |
|---|---|
| 「帮我完整解这道数模题并写成论文」 | `solve-full` |
| 「先做问题一，论文回头再说」 | `solve-only` |
| 「结果已经算好了，只帮我写论文」 | `paper-only` |
| 「这个 Gate 为什么没过」 | `gate-triage` |
| 「LaTeX 编译不过」 | `latex-fix` |

不需要背命令。路由自己匹配，workflow 在每一步给出要跑的门禁命令。

### 什么时候不该用它

- **只想问某个建模方法怎么用**——那是查资料，不必启动整条链路；
- **没有赛题、只有一堆数据**——先明确要回答什么问题，否则规格关过不了；
- **不打算留下可复算的数**——本 skill 的全部代价都花在这上面，不需要就别用。
