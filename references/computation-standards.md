# 实现与计算规范

## 1. 求解计划先行

每问动手前写 `求解/qN/PLAN.md`：方法与家族、输出文件清单及字段、依赖库、异常预案（不收敛/超时/内存不足怎么办）、预告证书等级（S1–S4 及证书类型）。

## 2. 单元测试与语义验收测试（先于主计算）

**A. 神谕独立性**：expected 来自手算、解析几何或独立算法（暴力点云、符号计算、极小规模精确求解），禁止 expected 由被测函数换壳自产。G3 审查时抽 1 个用例人工验算，同源即 R4 fail。

**B. 退化清单按原语类型选**（不是照抄名词）：
- 距离/相交类：零长、平行、共面、相切、端点落在边界、空集、单元素；
- 连通/可行类：空图、单点贯通、全满贯通、自环；
- 目标函数：全零决策、约束边界点、不可行点必须报不可行。

**B'. 距离原语禁止在源头 clamp**：距离/间隙类函数一律返回**有符号量**（负值 = 重叠/穿透深度），`max(0, ·)` 只允许出现在判据层且必须注释说明为何截断。理由有二：① 重叠深度是裕度证书与灵敏度分析的唯一输入，源头截断后所有下游裕度恒为 0 或 inf，证书结构性失效；② 函数 docstring 写"负值表示重叠"而实现 `return max(0.0, ...)` 属声明-实现不一致，G4 外部核验第 1 项直接判红。实测反例：题面允许介质重叠，距离全被截到 0，导致 `margin = 阈值/0 = inf` —— 三组数据全报"无穷裕度"，读者拿不到任何可核验数字。

**B''. 近似标定先于主计算（R1 硬项，实测反例：capsule 近似偏差 1.2% > Δ=0.01% 未被拦，阈值系统性偏低 5 根）**：任何几何/数值近似（capsule 距离、内接球、网格离散化、线性化）进主计算前，必须在标定样本（≥100 例，覆盖正常+退化+边界构型）上与精确方法逐例做差，产出 `结果/近似标定.md`：

| 近似名 | 精确方法 | 标定样本量 | max\|bias\| | Δ | bias/Δ | 结论 |
|---|---|---|---|---|---|---|
| capsule (d_seg-2r) | 平底圆柱表面距 | 200 | 0.012 | 0.0001 | 120 | 禁用，换精确 |

判定标准：**max\|bias\| ≥ Δ 即禁用该近似**（不是等"导通结论翻转"才禁——中间数值偏移 ≥ Δ 已使答案在题面精度下失真）。禁用时换精确实现或加偏差修正项；确需保留近似须在标定表写明修正公式与修正后残余 bias。只承认"近似是缺点"不量化影响 = 未标定 = R1 fail。G3 查 `结果/近似标定.md` 存在且每条近似有结论。

**B'''. 单测框架与覆盖**：单测用 pytest 框架（非脚本式断言），每个核心原语 ≥ 5 个用例覆盖正常/退化/边界/等变性/独立性；G3 抽查时数 < 50 属覆盖不足（实测 33 个脚本式断言 vs 基线 102 个 pytest，裁判 repro 直接扣分）。退化清单照 B 节按原语类型选。

**C. 语义验收测试**：把 P1 产出的 `结果/语义验收测试.md` 实现为**黑盒测试**——手工可判的微型构型 oracle、平移/旋转/置换等变性、守恒/材料总量对账、极限量级、跨问共核测试。期望值来自题面原文，不来自"采用口径"；测试不得调用生产判据的内部实现（共享核心函数即 fail），关键判据用第二独立实现或暴力小规模 oracle 做差分。

## 3. 共享内核与两阶段执行

- 核心原语与判据实现为单一模块 `求解/core/`，各问 import，禁止逐问复制或各写一版；内核变更后所有依赖问重跑（ledger 相应键标 stale）。
- 先算后画：计算脚本落盘 CSV/JSON（原始逐试验数据 + min/max/mean/std/CI），绘图脚本只读结果文件。

## 4. 分辨率预算（`结果/分辨率预算.md`）

| 结论 | Δ 及其来源 | 误差主导项 | 所需样本量/网格 | 单次耗时 | 预计总机时 | 实际预算 | 结论 |
|---|---|---|---|---|---|---|---|

- **Δ 来源优先级**（第一行写明，禁止自拟宽松 Δ）：① 题面明确精度；② 待比较方案目标差的 1/3；③ 决策变量最小单位。
- **过线判定**（与 R5 共用）：认证不确定度 u（= p̂ 与单侧认证下界之差）≤ Δ/3。"结论"列只能填：已分辨 / 未分辨故降级 / 换估计量后已分辨。
- **样本量按把握度排，不按临界点排**：`certify.py --solve-n --p-hat … --threshold …` 同时给 n_critical（真值≈p̂ 时一次终验只有约 50% 概率过线）与 n_power（90% 把握，通常约 3 倍）；证书协议是一次封存一次终验，机时必须按 n_power 排。
- 预计总机时 > 配额时按序处理：① 换高效估计量/算法（增量、充分统计量，通常一次给全曲线，收益最大）；② 内核加速（向量化、numba、消除 O(n²) 中间对象、预筛+精确两级过滤）；③ 并行；④ 才是降样本并同步降级结论与证书。
- 到总预算 20%/50%/80% 设检查点；80% 时仍不能预计获证，停止铺网格，切换证书策略或降级主张。

## 5. 证书计算

- **计划先行**：估计量、适用假设（Wilson/Clopper-Pearson 只适用于 iid Bernoulli；加权/相关/序贯须另给覆盖率依据）、置信水平、单双侧、**同时比较项数 K 与 alpha 分配**（格点扫描逐点认证时用 `certify.py --m K` 做 Bonferroni）、样本承诺、失败后唯一动作。
- **选择与认证分离**：扫描/比较可用共同随机数省样本；被选中方案封存后用独立种子终验。**一次封存、一次终验**：终验失败只能判不可行或重新进入选择并用全新批次，禁止反复换种子重测。
- **不达标处置顺序（不得跳步）**：① 用当前 p̂ 与阈值距离估算达标所需样本量，判断"真不可行还是区间太宽"；② 区间太宽：先换高效估计量或方差缩减，其次加算力，把区间收窄后在**原答案点**重判；③ 只有高精度下仍不可行，才把答案向保守方向移动并记录移动代价。**禁止用抬高答案替代提高精度**——小样本+保守门槛会系统性劣化最终数值。
- **答案稳定性复核**：最终答案点 ≥2 个独立主种子各重跑终验，按题目精度取整后答案必须不变；变化 = 预算不足，回 §4，不得挑好看的种子。结果进 ledger `stability` 字段。
- **多路独立互证（实测反例：单路增量法 vs 基线三路互证，裁判 algorithm 直接扣分）**：
  - **阈值/相变类问题（求"使 P≥阈值 的最小参数"）**：至少 **3 条独立估计路径**，来自不同模型族（非同族换参），例如：① 参数化拟合反解（Logistic/Probit/Weibull）+ 自助 CI；② 免函数形式直测（邻域加密扫描 + 局部插值）；③ 增量/序贯法（充分统计量一次出全曲线）+ 分位点。三路结果差异 ≳ Δ 必须定位原因（非仅声明"以直测为准"），定位不了须并报。
  - **非阈值类**：至少双路（主路线 + 核验路线），核验路线必须用不同估计量或不同算法族。
  - 差异写入 ledger `cross_check`；禁止取平均或择优报喜。
- 证书计算调 `scripts/certify.py --k … --n … --threshold … --delta …`（别手写公式），输出 JSON 直接填 ledger 的 certificate 块；不传 `--delta` 等于 R5 没判（ledger 校验会 WARN）。

## 6. 工程稳健性（长时计算防崩）

- 固定并记录随机种子（主种子 + 每 worker 派生）。
- 增量落盘：每完成一个参数点/一批试验立即 append，崩溃可续；配心跳日志（进度/预计剩余）。
- 并行留余量：worker ≤ CPU 核数 − 1 且总内存估算 < 可用内存 70%；大数组分块，禁一次性物化 O(n²) 大对象。
- 超 10 分钟的计算先 1% 规模冒烟跑通全链路（含落盘和绘图）再放量。

## 7. 数字治理与合理性检查

### results_ledger.json（论文数字唯一来源，schema 由 `scripts/ledger.py --validate` 机检）

```json
{
  "q2_main_metric": {
    "quantity": "q2_主指标@档位4",
    "value": 0.9933, "unit": "1", "display": "99.33%",
    "role": "authoritative",
    "source": {"script": "求解/q2/scan.py", "params": "level=4, n=40000, seed=20260813",
               "file": "结果/q2_scan.csv", "field": "p_hat[level=4]"},
    "certificate": {"family": "wilson_lower_95", "bound": 0.9917, "n": 40000,
                    "threshold": 0.90, "pass": true,
                    "delta": 0.005, "u": 0.0016, "resolved": true},
    "depends_on": ["求解/core/judge.py", "附件1.xlsx"],
    "cross_check": {"path2_value": 0.9928, "diff_vs_delta": 0.15},
    "stability": {"seeds": 2, "stable": true},
    "status": "frozen"
  }
}
```

必填字段：`value / unit / display / role(authoritative|cross_check|intermediate) / source{script, params, file, field} / status(draft|frozen|stale)`。certificate 块直接用 `certify.py` 的 JSON 输出填（此为 M1 示例；M2 用 gap 字段、M5 用 conv_order 字段，禁止照抄 wilson）。`source.file + source.field` 是三向审计能回读复算的前提（field 写法：JSON `a.b[2].c`；CSV `列名@行号` 或 `列名[键列=键值]`），缺了审计退化成两向 = R6 fail。

- **唯一权威答案**：每个被问量（`quantity`）有且只有一条 `role: "authoritative"`；其余同量记录标 `cross_check` 并注明差异与取舍。摘要/正文结论/图题只引用权威值。`ledger.py --validate` 会查重。
- **stale 传播**：入账后跑 `ledger.py --freeze` 记录 `depends_on` 的 SHA-256；上游变更后 `ledger.py --stale-check --write` 自动标 stale；stale 键不得回填论文，G6 审计发现即 fail。
- 数字回填：`ledger.py --emit-tex -o 论文/numbers.tex` 生成宏（含 Bound/N/Threshold/Gap/Unit 派生宏），正文关键数值只引用宏。
- **三向审计**：`audit_numbers.py --ledger … --numbers … --tex 论文/main.tex --out 结果/审计报告.md`——论文 ↔ ledger ↔ 磁盘结果文件逐条回读复算比对；脚本列出的"未走宏可疑数字"逐条人工裁定。审计必须理解统计语义，不是只查文件存在。

### 合理性检查（G3 硬项，`结果/合理性检查.md`，进 ledger 前逐项过）

1. **极限/退化情形**：参数趋 0/趋极大/单元素/空集时结果趋向理论必然值（概率→0 或 1、成本→0）。
2. **单调性与形状**：随控制变量的变化方向符合机理；非单调必须解释是噪声还是结构（附样本量与区间）。
3. **量纲与量级**：单位逐条核对；用 5 行粗估模型（解析近似、平均场、理论界、经验公式）独立算一遍比量级；**差一个数量级以上必须停下查代码，不得写进论文**。
4. **跨问互恰**：各问结果间的必然关系成立（如某问阈值应落在另一问相邻档之间；优化最优成本应 ≥ 单方案成本下界）。
5. **退化输出识别**：全 100%/全 0/各档无区分度/结果与输入无关，默认判实现 bug，定位到代码行才放行。

任一项异常且无法解释即 R1 红。

## 8. 交付代码要求

- 一键复现入口（run_all.py 或 Makefile），README 写明环境、依赖版本、预计运行时间。
- **数字→脚本可达**：ledger 每条 source.script 存在于交付包内且被 run_all 某条路径调用到；"论文有数、包里没代码" = R6 fail。
- **自含性**：包内含或声明原始附件相对路径；复现命令在解压后的交付目录内即可跑通，不依赖包外绝对路径。
- **覆盖防护**：汇总类结果文件分问命名 + 合并脚本，防止最后一次单问运行冲掉总表。

## 对照实验默认配对（2026-09-03）

比较两种方法/口径/近似时，**共用同一批随机构型**（配对设计），不要各自独立抽样。

- 独立抽样时两臂的差异被抽样方差淹没，需要成倍样本才看得出效应；配对后方差大幅下降，同样机时能测出更小的效应。
- 标杆交付物用 2 万条**逐路径配对**测出"精确判据使首次贯通平均晚 5.70 根"这种量级的效应——独立抽样测不到。
- 实现要点：同一 seed 序列生成构型，两臂各自判定，逐条求差，对差值做统计而不是对两个均值做差。
- 报告时写明"配对"以及配对带来的方差收益，否则读者无法判断你的样本量够不够。

## 长数值实验必须可恢复（2026-09-03 血的教训）

**默认模式是"分块 + 原子落盘 + 恢复扫描 + 到时语义"，不是 `pool.map` 一把梭。**

同一台机器上连续发生两次全损：

| 次 | 现象 | 损失 |
|---|---|---|
| 1 | 线程资源竞争，进程停止，中途无落盘 | 1.5 小时算力清零 |
| 2 | 系统无法创建任何新进程（Windows `0xc0000142`，DLL 初始化失败，连 `git` 都起不来） | 又 1.5 小时清零 |

根因同一个：`pool.map` 跑完才返回，中途一个字节都不写盘；6 小时的批次等于 6 小时的全有全无赌局。

**硬要求：**

1. **块上限**：每块 ≤500 个计算单元，一块跑完立刻落盘。
2. **原子落盘**：先写临时文件再 `os.replace`，避免半截文件被当成完成块。
3. **恢复扫描**：启动时扫已有块并跳过，天然支持断点续跑。
4. **到时语义**：设硬性 wall-clock 预算，到点用**已完成的块**出结论，
   并如实声明实际样本量、与计划的缺口、对置信区间的影响。
   **宁可交一份样本量不足但如实声明的完整交付物，也不要赌一个跑不完的全量批次。**
5. **worker 数留余量**：32 核机器上单路 ≤14；多路并行时按路数均分。
   长任务加 `maxtasksperchild` 回收子进程，防止句柄与桌面堆累积耗尽（这是上面第 2 次全损的直接原因）。

## 测试必须覆盖四层（2026-09-03 横比教训）

只测核心原语是不够的。横比中做得最好的那份候选有 11 个测试文件，覆盖：

| 层 | 测什么 | 例 |
|---|---|---|
| 原语层 | 几何/数值核心函数，含退化情形 | `test_geometry` |
| 统计层 | 证书计算、选点逻辑、样本量元数据 | `test_analysis_selection` |
| **论文层** | LaTeX 源可编译、宏文件被正确 `input`、正文无裸数字 | `test_latex_source`、`test_paper_numbers_input` |
| **图层** | 图文件存在、被正文引用、由结果数据生成 | `test_figures` |
| 复现层 | 同种子重放一致、打包后路径自洽 | `test_local_replay`、`test_resumable` |

我方历史交付物只有 1 个测试文件，且只测原语层——论文层与图层完全裸奔，
"7 张图只进 1 张""main.tex 漏写 input{numbers.tex}"这两个真实事故都本该被这两层拦住。
