# 本赛事交付与门禁

> 触发条件：为本赛事写论文、整理附录/支撑材料，或进入 P7 打包前阅读。
> 本文只定义这次比赛的交付边界；建模、数值和图表质量仍按对应 workflow 的证据链执行。

## 最终包

中间产物只能放在工作区的 `tmp/`，不能进入提交目录。最终包的最小形态如下：

```text
交付/
  论文.pdf
  delivery-manifest.json
  reproduce.py
  支撑材料/
    source/                         # 完整、可运行的源码
    AI工具使用详情.pdf              # 仅实际使用 AI 时提交
    data/                           # 仅自行获得的数据，按需提交
    results/                        # 论文放不下的结果，按需提交
```

`delivery-manifest.json` 用 `assets/delivery/delivery-manifest.json` 为起点。它连接论文、支撑材料、完整源码入口、复现入口与附录标签；所有路径使用 `/` 形式的包内相对路径。

## 论文与 AI

论文末尾的顺序是：模型改进、简要 AI 工具使用声明、参考文献、附录。现有 `assets/paper/8.模型改进推广.tex` 已把简要声明放在参考文献之前，保持该位置，不新增第二段声明。

- 实际使用 AI：论文只写真实、简短的用途说明；支撑材料提交 `AI工具使用详情.pdf`；附录不列出或复述该 PDF。
- 未使用 AI：使用未使用声明，不提交或列出 AI 详情 PDF。
- AI 工具不是学术参考文献，不能写入参考文献表。
- 不得把模板中的工具、日期、提示词、结果或机构名称当作事实填写。

独立模板在 `assets/supporting-materials/AI工具使用详情.tex`。它覆盖工具身份、七个工作阶段、提示方式、2--3 条代表性交互、采纳/人工修改/核验，以及团队主导性确认。只记录实际发生的内容，绝不补造对话或验证。

## 附录与支撑材料

附录应让评委理解和定位复现材料，而不是打印整个项目：

1. 列出需要在论文附录中指路的支撑文件的相对路径、类型、作用和论文/附录位置。
2. 说明实际软件环境、输入输出和复现命令。
3. 放与模型论证直接相关的核心代码节选。
4. 明确完整可运行源码在 `支撑材料/source/` 的入口文件。
5. 可补充长证明、复杂图表和大结果文件，但竞赛提供的原始数据不重复提交。

核心节选帮助阅读；完整源码才承担复现。两者不能互相替代。

## 分层门禁

`python scripts/delivery_gate.py 交付/` 不用固定篇幅或数量配额冒充质量检查。它的四层是：

1. **明文契约**：manifest 是否声明 PDF、AI 使用状态、完整源码入口、复现入口和附录标签。
2. **包边界**：声明路径是否存在、是否越出包外、支撑材料是否落在正确目录、是否夹带 `tmp/`。
3. **交叉关系**：提供 `--appendix-source` 后，附录标签和源码入口是否与 manifest 一致；AI 详情只核对清单与包内文件。
4. **行为记录与人工审查**：门禁写 JSON 报告；团队另运行 `reproduce.py` 并记录命令、退出码和证据路径。

不要为了一个静态文件清单引入 TLA+。它不能证明科学正确性、真实 AI 使用、完整运行效果或匿名性；这些必须由真实复现和人工复核完成。

P7 的最低命令序列：

```bash
python scripts/delivery_gate.py 交付/ --appendix-source 论文/10.附录.tex \
  --out 结果/gates/G7-交付清单.json
python 交付/reproduce.py
python scripts/pkg_scan.py 交付/ --out 结果/gates/G7-出门扫描.json
```

三条命令的退出码、执行时间、实际环境与证据路径写入 Gate 记录。`delivery_gate.py` 先验证包关系，`reproduce.py` 再执行真实最小复算，`pkg_scan.py` 负责泄露、绝对路径和中间产物扫描。

## 必须人工核验

交付前逐项核对：论文和 PDF 元数据、附件文件名、源码注释、路径、截图中没有队员身份；AI 简要声明、详细 PDF 与实际记录一致；源码确实完整可运行；数据来源、许可和脱敏合适；论文中每个科学结论都有真实结果与验证支持。
