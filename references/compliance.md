# 赛制合规与打包

合规漏项可导致**取消评奖资格**，与算法无关但一票致命。P0 先把章程/格式规范读全并摘录硬性条款到 `结果/合规摘录.md`；P7 打包前逐项过检查单。

## 合规检查单（按该赛事章程逐条核实，以下为常见硬性项）

- [ ] **AI 使用声明**：赛事要求披露 AI 工具使用时，按规定格式在指定位置（通常论文末或附录首）如实声明工具与用途。漏报可取消评奖资格。
- [ ] **文件命名**：按赛制要求（常见"题号+参赛编号"）；所有交付文件统一口径。
- [ ] **匿名性**：正文、页眉页脚、PDF 元数据（作者字段）、代码注释中无学校/姓名/指导教师信息。
- [ ] **首屏信息**：承诺书/编号页按模板填写，占位符全部替换为真实值；拿不到真实队号时显式标注待填并列为阻塞项，禁止留假值。
- [ ] **页数/摘要要求**：摘要页数程序化核实（.aux）；正文页数与章程上限/建议值比对——超出建议值必须先执行 paper-latex 的分层压缩（明细入附录），仍超则记录为知情扣分项并说明原因。
- [ ] **附录要求**：章程要求附代码/数据的，核实已附且可读。
- [ ] **原创性**：引用有出处；参考文献真实存在。

## 打包闭环（防"门禁只查工作区不查交付包"）

1. 写交付清单 `交付/manifest.md`：逐文件列相对路径、SHA-256、字节数、用途、生成命令。
2. 组装交付目录后，**在交付目录内**逐项比对 manifest ↔ 实际文件：存在性、文件名、哈希、大小非零。
3. **复现闭环**（在交付目录内，不是工作区）：
   a. README 一键命令必须调用与 ledger 的 source.script 相同的入口；
   b. 用最小可核对子集（确定性问全量 + 1 个主结论按认证种子小比例重跑并核对方向）再生 ledger 对应键，文件名逐一对应；
   c. 论文引用的每个 CSV/JSON 必须能被 run_all 写出；写不出 = G7 fail。
4. 压缩打包后解压抽查一次（防遗漏/路径错乱）。
5. 全部通过才算 G7 过；任何一项 FAIL 修完后从第 2 步重来。
