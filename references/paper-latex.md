# 论文写作与 LaTeX 编译

## 论文工程形态：分节 tex + 主控编译（钉死）

论文一律拆成**分节 `.tex`**，由 `main.tex` 用 `\input` 装配后统一编译，禁止把全文塞进单文件。

- 收益：编译错误的行号落在具体一节里可定位；出完数的问先写先编译，不被还在算的问阻塞；改一节不必重排全文，修错循环更快；某一问写长了可再拆成「分析与准备 / 建模与求解」两片。
- 骨架与分节清单见 `assets/paper/`（该目录 README 含编译修错速查表）。
- 有官方模板时：把官方 class 换进 `main.tex`，`\input` 结构照旧——分节是工程形态，与模板归属无关。

## 结构模板（中文赛事通用；美赛等按官方模板对应调整）

1. 摘要：逐问一句"方法 + 关键数值结论"，末句总括模型特色。摘要是评委唯一必读页，数字必须与正文一致且 ⊆ ledger 证书达标条目。
2. 问题重述（简明，不抄题面）
3. 模型假设：每条附合理性依据；**口径决策表的披露版**放这里（采用口径 + 被否口径的定量归谬一句话）
4. 符号说明表
5. 每问三段式：问题分析与准备 → 模型建立与求解 → 结果检验（证书、收敛、双路互证）
6. 灵敏度与稳健性分析（独立成节）
7. 模型优缺点与改进方向（如实写实际达到的强度等级 S1–S4）
8. 参考文献（真实存在、格式统一）
9. 附录：核心代码、明细表、推导全过程、次要对照、复现说明

## 篇幅底线：四问论文正文低于 25 页 = 没写透

同题的人工基线交付物是 37 页。**不足 25 页不要交稿**——差的不是文采，是这些没写出来：

| 通常缺的部分 | 补法 |
|---|---|
| 每问的结果检验 | 双路互证、证书、与参考值对表，各问独立成小节 |
| 灵敏度分析 | 参数扰动 → 结论是否翻转，给数字 |
| 机理讨论 | 为什么是这个数，物理/结构上的解释 |
| 图表解读 | 每张图配一段"看出什么"，不是只放图 |
| 分层附录 | 复现说明、核心代码、结果明细表、推导全过程、AI 声明 |

**注水比短更糟**：空洞形容、复述题面、重复图表、把一张表拆三张——paper 与 rules 两维同时丢。章程有硬性上限时以章程为准。

## 篇幅口径：完整性优先的对象是证据链，不是页数

- P0 已摘录规范页数条款（硬上限还是建议值、是否含附录）。
- 正文只承载**证据链主线**：模型设定、关键推导结论（过程移附录）、主结果数值与证书、每问 1–2 张最关键的图、检验结论。
- 明细表、逐点扫描表、推导全过程、次要对照实验、源码、非关键图一律进附录。
- 章程有建议页数时争取正文落在建议值内（无建议值按每问 3–5 页 + 前后置 4–6 页估算）——**这是 rules 维不失分的必要动作**。
- 删节判据："删掉是否丢失证据链一环"——会丢的**移附录而不是删**，不会丢的删。不为凑页数注水。
- 实在压不进建议值时，在 `结果/gates/G7.md` 记录"已知格式扣分项 + 已做的压缩措施"，让扣分是知情选择而非疏忽。

## 数字回填

- `python scripts/ledger.py --emit-tex 结果/results_ledger.json -o 论文/numbers.tex` 生成宏（宏名由键名派生，含 Bound/N/Threshold/Gap/Unit 派生宏），正文关键数值**只引用宏**。无官方模板时用分节模板包 `assets/paper/`（主控 `main.tex` + 13 个分节 tex，预留 numbers.tex 注入位与附录分层；有官方模板时只沿用其分节装配结构，不得覆盖官方 class）。
- 宏注入失败时的人工核对仅为临时措施：审计报告必须逐条给出论文页码 + ledger 键，禁止凭记忆手抄。
- 结果章节出现的裸数字（非年份/章节号/引用号）都应可追溯到 ledger；G6 审计逐条比对。

## 自审三轮（成稿后、编译前）

1. **Claim-Evidence 映射**：逐结论填"结论 → 证据（图/表/ledger 键/代码位置）→ 强度等级"。指不到证据的删除或降级。
2. **反过度主张扫描**：全文搜 `最优|最低|证明|显著|必然|可忽略|严格|满足约束|可行|达标|推荐方案|最终答案|全局`，逐词核对证书等级与 R3 声明级别；S3 证据禁用 S1 措辞（改"统计证据支持""95% 置信下界满足""在已搜索集合 S 内未发现更优"）。**摘要与结论中每个数字 ⊆ ledger 中证书达标的 authoritative 条目；机会约束数字旁必须出现下界值**（不能只有点估计）。
3. **终审强度校准**：对摘要 + 结论 + 各问最终答案重跑 depth-review 第一问（分层）与第二问（gap 审计），与 P4 各问分层表比对，措辞强度不得高于任何一处实际等级；落盘 `结果/审查/终审强度校准.md`。

**答案唯一性扫描**（随第 2 轮做）：每问最终答案在摘要/正文/图表/结论中是同一个数（含精度/取整口径一致）；交叉验证值只出现在检验小节或附录并注明"用于互证，不作为答案"。

## 去 AI 味写作铁律

- 结果描述三要素：**数字 + 比较 + 机理**，禁止空洞形容词（"效果显著""性能优异"）。
- 不用套话开头（"随着…的发展"）；不写"本文创新点如下"式自夸列表，创新让证据说话。
- 删掉任何一句话若不损失信息，就删。

## 编译契约与编译链

1. **模板契约优先**：有官方模板/指定编译链时严格照用（class、引擎、bib 工具、页数规则、命名），禁止擅自替换引擎或加宏包（如给英文赛事模板加 ctex）。无官方模板且中文写作才默认 xelatex + ctex。
2. 优先 `latexmk -xelatex -halt-on-error -interaction=nonstopmode` 并**检查退出码**；无 latexmk 则编译 ×2 保证交叉引用收敛；有 bib：xelatex → biber/bibtex → xelatex ×2，不得只跑 ×2。
3. **门禁分类交给脚本**：`python scripts/latex_gate.py 论文/main.log --aux 论文/main.aux [--whitelist 结果/编译白名单.md]`。阻断项（清零才过 G7，以脚本实现为准）：真实错误 `^!`、LaTeX Error、未定义命令、未定义引用、未定义引文、未定义汇总行、缺文件、缺字形、Float too large、Overfull。缺字体换系统可用字体并写回退链，不得静默降级。空图框在 log 里无对应字符串，由 G5 的 figqa 与 PDF 目检负责。
4. **Underfull 政策**：仅处理 badness 超阈值且 PDF 目检可见的条目；残余 warning 记 `结果/编译白名单.md` 及理由，复检时不得新增。
5. 常用修法：长公式断行、表格 tabularx、图宽 0.9\linewidth、长 URL 断字。
6. 摘要页数验证：赛制要求一页时 `latex_gate.py --abstract-label` 从 .aux 程序化核实，不靠目测。
7. 产物检查：PDF 页数、书签、图全部渲染、字体嵌入。

## 摘要与结论的呈现（2026-09-04，来自真实评委反馈）

同题一份 53 页交付物的评审意见原文要点：

> 摘要结构完整，能够准确概括四问的模型、关键数值和主要结论，信息组织较强；
> **但部分技术细节略密，可进一步突出核心创新和最终成果。**
> …写作排版方面，结构清晰，公式、图表和结果表组织较规范，整体可读性较好；
> **但少量技术细节略显冗长，关键结论还可更醒目地集中呈现。**

两条批评指向同一件事：**该突出的没突出，不该细的太细。**

### 摘要：只回答「用什么算法、得到什么结果」

- 每问一句，句式统一；每句 = 问题类型定性 + **算法名（加粗）** + **结论与关键数字（加粗）**。
- 技术细节（参数如何选、边界如何处理、为何不取另一口径）**一律留正文**，摘要里出现即为冗余。
- **加粗规则**：评委扫读时视线只停在粗体上。算法名与最终结论/数字必须加粗；
  但一句里粗体不超过两处——粗体太多等于没有粗体。
- 删节判据：删掉一句若不损失「算法或结果」的信息，就删。
- 末句点核心创新——这是评委找创新点的位置，空着等于放弃。

### 正文：关键结论要「醒目地集中呈现」

- **每问末尾放一个结论块**（`\begin{tcolorbox}` 或加框 `\fbox`／带底纹的 `mdframed`，无宏包时用带上下横线的居中段落），
  内容只有三行：最终答案（数字走宏）、证书（样本量 + 下界 + 判定）、一句话适用条件。
- **全文放一张结果汇总表**（通常置于结论章或检验章之前）：一行一问，列出
  「问题 / 模型类别 / 求解算法 / 最终答案 / 证书 / 所在章节」。评委据此一眼定位全部结论。
- 冗长的技术细节移附录：推导中间步骤、逐点扫描表、参数敏感性明细、实现层面的工程细节。
  正文只留「设定 → 关键结论 → 检验」这条主线。
